# Установка, обновление и удаление

Текущий стабильный выпуск —
[`v0.0.4.0`](https://github.com/aVitomin/runet-censorship-bypass-mv3/releases/tag/v0.0.4.0).
Выберите отдельную инструкцию для Chromium или Firefox: файлы и способ
установки у них различаются.

## Требования и проверенные версии

- **Firefox:** минимальная версия, заданная расширением, — 154.0. Выпуск
  проверен в Firefox 154.0.1.
- **Chromium:** отдельная минимальная версия в расширении не задана. Нужен
  современный браузер с используемыми MV3 API. Выпуск проверен в Chrome
  153.0.8010.37, Edge 153.0.4234.32 и Brave 1.95.101.

Яндекс Браузер, Opera, Vivaldi и другие современные Chromium-браузеры могут
быть совместимы, но в проверку выпуска не входили. Это не гарантия работы во
всех Chromium-форках.

## Chromium: установить стабильный ZIP

### 1. Скачать и проверить

Откройте
[`v0.0.4.0`](https://github.com/aVitomin/runet-censorship-bypass-mv3/releases/tag/v0.0.4.0)
и скачайте именно
[`runet-censorship-bypass-mv3-0.0.4.0-7c0c64c.zip`](https://github.com/aVitomin/runet-censorship-bypass-mv3/releases/download/v0.0.4.0/runet-censorship-bypass-mv3-0.0.4.0-7c0c64c.zip),
а не автоматически созданный **Source code**.

Ожидаемый SHA-256:

```text
e702dff6ba3fe9bb3291de413c4e106f95dcd9b83f9cf8fc98f9635f5990f236
```

Файл проверки:
[`runet-censorship-bypass-mv3-0.0.4.0-7c0c64c.sha256.txt`](https://github.com/aVitomin/runet-censorship-bypass-mv3/releases/download/v0.0.4.0/runet-censorship-bypass-mv3-0.0.4.0-7c0c64c.sha256.txt).

В PowerShell:

```powershell
Get-FileHash .\runet-censorship-bypass-mv3-0.0.4.0-7c0c64c.zip -Algorithm SHA256
```

Не устанавливайте архив, если хэш отличается.

### 2. Распаковать и загрузить

1. Полностью распакуйте ZIP в постоянную папку.
2. Откройте страницу расширений браузера.
3. Включите **Developer mode / Режим разработчика**.
4. Нажмите **Load unpacked / Загрузить распакованное расширение**.
5. Выберите папку, где `manifest.json` находится непосредственно в корне.
6. Закрепите значок расширения на панели.

| Браузер | Страница расширений | Статус для `0.0.4.0` |
| --- | --- | --- |
| Google Chrome | `chrome://extensions` | Проверен |
| Microsoft Edge | `edge://extensions` | Проверен |
| Brave | `brave://extensions` | Проверен |
| Яндекс Браузер | `browser://extensions` | Ожидается совместимым |
| Opera | `opera:extensions` | Ожидается совместимым |
| Vivaldi | `vivaldi://extensions` | Ожидается совместимым |

Если специальный адрес отличается, откройте меню браузера и найдите раздел
**Extensions / Расширения**. Папку установленного распакованного расширения нельзя
перемещать или удалять: браузер продолжает читать файлы из неё.

Яндекс Браузер может отключать расширения из непроверенного источника после
перезапуска. Это
[ограничение браузера](https://yandex.com/support/browser/en/security/check-extensions?lang=ru),
а не состояние **Активно** внутри расширения.

## Firefox: только подписанная пользовательская установка

1. Скачайте Mozilla-подписанный
[`runet-censorship-bypass-firefox-0.0.4.0-signed.xpi`](https://github.com/aVitomin/runet-censorship-bypass-mv3/releases/download/v0.0.4.0/runet-censorship-bypass-firefox-0.0.4.0-signed.xpi)
из опубликованного GitHub Release.
2. Откройте XPI в Firefox и подтвердите установку и запрошенные разрешения.
3. На странице `about:addons` разрешите расширению работу в приватных окнах.
   Без этого Firefox не позволит применить общую настройку прокси.
4. Закрепите значок расширения на панели.

Ожидаемый SHA-256:

```text
c7e3042e48819644673db92b9150a9d54a551281046212d896a7f7202bc9c34c
```

Файл проверки:
[`runet-censorship-bypass-firefox-0.0.4.0-signed.sha256.txt`](https://github.com/aVitomin/runet-censorship-bypass-mv3/releases/download/v0.0.4.0/runet-censorship-bypass-firefox-0.0.4.0-signed.sha256.txt).

Публичной страницы расширения в каталоге Mozilla Add-ons (AMO) пока нет. Не
обходите проверку подписи и не используйте неподписанный тестовый XPI как
обычную пользовательскую версию. Временная установка через `about:debugging`
предназначена для разработки и может исчезнуть после перезапуска.

## Первый запуск

### Chromium

1. Откройте значок расширения и перейдите к настройке.
2. В разделе **Автоматическая маршрутизация** выберите источник правил.
3. Нажмите **Применить конфигурацию** и дождитесь состояния **Активно**.

Встроенный источник может содержать собственные прокси-маршруты. Режим
**Только ручные правила** их не содержит, а явному режиму **Через прокси**
нужно хотя бы одно настроенное подключение. Требования пользовательского
источника определяются его PAC-файлом.

### Firefox

1. Убедитесь, что разрешена работа расширения в приватных окнах.
2. Откройте значок расширения и нажмите **Включить** или **Применить**.
3. Дождитесь состояния **Защита активна**.

Firefox уже содержит набор правил Anticensority. Его автоматическая
прокси-цепочка ожидает доступные локальные службы Anticensority и, как запасные
варианты, Tor Browser или Tor. Расширение не устанавливает и не запускает эти
службы. Собственный прокси для явного режима **Прокси** настраивается отдельно.

Значение режимов и точные требования подключений описаны в
[руководстве пользователя](USER_GUIDE.md).

## Обновить расширение

Обновление расширения заменяет его код и версию. Это не то же самое, что
обновление данных автоматической маршрутизации в разделе обслуживания.

### Chromium: сохранить ту же установку

1. В расширении нажмите **Выключить прокси расширения**, чтобы вернуть исходную
   настройку прокси браузера.
2. Скачайте новый ZIP только со страницы
   [Releases](https://github.com/aVitomin/runet-censorship-bypass-mv3/releases).
3. Проверьте SHA-256 и распакуйте архив во временное место.
4. Полностью замените файлы внутри **той же постоянной папки**, которая уже
   загружена в браузер. Не смешивайте файлы разных версий и не меняйте путь к
   установленной папке.
5. На странице расширений нажмите **Reload / Перезагрузить** у существующей
   карточки.
6. Проверьте версию и сохранённые настройки, затем явно примените конфигурацию.

Не рассчитывайте, что **Load unpacked** из другой папки сохранит настройки:
путь может участвовать в идентичности распакованного расширения, и браузер может
создать вторую установку с другим хранилищем.

### Firefox: установить следующий подписанный XPI

До появления публичной страницы в каталоге Mozilla проверяйте новый GitHub
Release и открывайте следующий Mozilla-подписанный XPI вручную. Firefox обычно
распознаёт подписанный XPI с тем же идентификатором расширения как обновление;
после установки всё равно проверьте версию, настройки и состояние защиты. Не
заменяйте подписанную установку временным неподписанным дополнением.

## Обновить только данные маршрутизации

- В Chromium раздел **Обслуживание / Maintenance** может обновить данные
  выбранного источника. Обновление данных не устанавливает новую версию
  расширения и само по себе не включает выключенный прокси.
- В Firefox `0.0.4.0` удалённый канал данных не настроен. Состояние
  **Не настроено / Not configured** ожидаемо: ручная и фоновая загрузка
  отключены, а встроенный набор продолжает использоваться. Новый встроенный
  набор может прийти с будущим обновлением самого расширения.

## Удаление

1. Если расширение активно, нажмите **Выключить прокси расширения** в Chromium
   или **Выключить** в Firefox, чтобы вернуть исходную конфигурацию прокси.
2. Удалите расширение на странице расширений браузера.
3. После удаления Chromium-карточки можно удалить её постоянную распакованную
   папку.

Расширение не очищает настройку, принадлежащую другому расширению или политике.
Если установка, применение или восстановление настройки прокси не работают, используйте
[решение проблем](TROUBLESHOOTING.md).

## English summary

Firefox requires 154.0 or newer; `0.0.4.0` was tested with Firefox 154.0.1.
Chromium has no separate minimum version in its manifest; the release was tested
with Chrome 153.0.8010.37, Edge 153.0.4234.32, and Brave 1.95.101. Other modern
Chromium browsers were not separately release-tested.

The current stable release is the dual-browser `v0.0.4.0`. Chromium users
download and verify the published ZIP, extract it, enable **Developer mode**,
and choose **Load unpacked**. Keep an unpacked Chromium update at the same path;
loading a different folder may create a different extension identity and does
not promise settings preservation. Firefox users install the Mozilla-signed XPI
from the same GitHub Release. No public AMO listing exists for the new Firefox
ID yet; unsigned XPI loading is only for temporary developer/reviewer testing.

Extension updates and automatic-routing data updates are separate. Remote data
updates are not configured in Firefox `0.0.4.0`; the packaged dataset remains
available.
