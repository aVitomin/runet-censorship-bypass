# Приватность и безопасность

Коротко:

- расширение видит имя сайта, чтобы выбрать маршрут;
- оно не отправляет разработчикам телеметрию или аналитику;
- оно не предоставляет VPN или прокси и не гарантирует анонимность, сокрытие IP
  либо отсутствие DNS-утечек;
- выбранный прокси или локальный сервис может видеть адрес назначения и
  доступную ему часть трафика;
- настройки и учётные данные собственного прокси хранятся в локальном
  хранилище браузера.

Расширение не внедряет код в страницы для аналитики. Оно получает сетевые
разрешения, потому что должно выбрать прямой или прокси-маршрут и при необходимости
ответить на запрос аутентификации прокси.

Текущий опубликованный [`v0.0.4.0`](https://github.com/aVitomin/runet-censorship-bypass-mv3/releases/tag/v0.0.4.0)
содержит Chromium-пакет и Mozilla-подписанный Firefox XPI.
Эта страница описывает его границы. Изменения для ещё не выпущенной версии,
включая перенос настроек и файлы для поддержки, описаны отдельно в
[подготовке 1.0](../development/UPCOMING_1_0_USER_GUIDE.md#перенос-настроек-и-файл-для-поддержки).

## Кому могут быть видны сетевые данные

- При **Напрямую / Direct** сайт и обычная сетевая инфраструктура видят
  соединение так же, как без прокси расширения.
- При **Прокси / Proxy** выбранный прокси видит адрес назначения и сетевые
  данные в пределах протокола и шифрования. Используйте только доверенные
  серверы.
- Источник автоматической маршрутизации определяет правила, но это не делает
  расширение VPN-провайдером. Firefox использует локальный набор; Chromium
  может загружать выбранный источник.
- Tor, Tor Browser и WARP работают только через локально запущенные приложения;
  расширение не запускает их и не обещает их анонимность.

## Что хранится локально

- Правила сайтов, переключатели и прокси-подключения.
- Проверенные данные маршрутизации и служебная информация, нужная для
  восстановления после перезапуска фонового процесса.
- Имя пользователя и пароль собственного прокси, только если пользователь явно
  их настроил.

Прокси-пароль хранится отдельно от правил маршрутизации. После сохранения
интерфейс знает только, нужно ли сохранить, заменить или удалить пароль; само
значение не возвращается в страницу настроек, панель, диагностику, уведомления,
ошибки или логи. Удаление расширения обычно удаляет его хранилище браузера;
облачной резервной копии продукт не предоставляет.

## Разрешения браузера

### Chromium

- `proxy` — применить и снять конфигурацию маршрутизации расширения;
- `storage` и `alarms` — хранить настройки и восстанавливать расписание;
- `webRequest` и `webRequestAuthProvider` — получать события сетевых запросов
  и отвечать на поддерживаемые запросы аутентификации настроенного прокси;
- `activeTab` — определить текущий сайт для Авто / Прокси / Напрямую;
- `notifications` — редкие сообщения о состоянии, требующем действия.

Широкий сетевой доступ нужен для выбора маршрута и аутентификации, а не для
добавления скриптов на каждую страницу.

### Firefox

Firefox использует `proxy`, `webRequest`, `webRequestBlocking`, `storage`,
`alarms`, `notifications` и `<all_urls>` для маршрутизации, поддерживаемой
аутентификации прокси, восстановления и безопасного выключения.

Манифест Mozilla декларирует категории доступа `authenticationInfo` и
`browsingActivity`: расширение обрабатывает запрос аутентификации и имя сайта,
чтобы выбрать маршрут. Это обязательное описание доступа, а не отправка данных
разработчикам. Телеметрия отсутствует.

Для применения в Firefox нужен доступ к приватным окнам, потому что настройка
прокси общая. Если разрешение отозвано во время работы, соответствующие
обработчики отключаются и маршрутизация блокируется; выключение защиты остаётся
доступным без повторной выдачи разрешения.

Разрешение выдаёт пользователь в **Дополнения и темы → Расширения → карточка
расширения → работа в приватных окнах**. Расширение не может включить его само.
Доступ к ограниченным Firefox сайтам выдаётся отдельно: он не является
предварительным условием включения защиты, и расширение не показывает его как
проверенное разрешение. Служебные страницы `about:` — не обычные сайты для
выбора маршрута.

## Сетевые обращения расширения

- Chromium принимает пользовательский источник только по HTTPS или HTTP для
  локального адреса компьютера, запрещает учётные данные в URL и повторно проверяет
  перенаправления, размер и кодировку.
- Firefox поставляет проверенный локальный набор данных. Адрес и публичный ключ
  удалённого обновления пока не настроены, поэтому ручная и фоновая загрузка
  отключены. Встроенный набор продолжает работать.
- **Проверка подключения** запускается пользователем, не отправляет cookies или
  учётные данные сайта и не меняет правила, данные или владение настройкой
  прокси. Если поддерживаемый HTTP/HTTPS-прокси запросит аутентификацию,
  расширение может передать ему сохранённые учётные данные прокси; в
  диагностическом результате они не показываются.

Загруженные правила Chromium проверяются, прежде чем передать их браузеру.
Это не делает владельца источника автоматически доверенным. Firefox использует
проверенные правила, включённые в расширение. Свежие правила не гарантируют,
что настроенная прокси-служба доступна.

## Границы защиты

- **Chromium:** если браузерный механизм выбора маршрута
  даст сбой, возможно прямое соединение. Поэтому Chromium нельзя считать
  полностью блокирующим соединения при любой ошибке.
- **Firefox:** если все прокси автоматической цепочки недоступны, запрос
  завершается ошибкой вместо перехода на прямое соединение. Потеря контроля или
  отозванный доступ к приватным окнам также останавливает активную сессию, не
  перезаписывая чужую настройку прокси.

Ни значок панели, ни проверка подключения не доказывают маршрут каждого
вспомогательного запроса, отсутствие DNS-утечек или будущую доступность прокси.

Защитный механизм Firefox использует локальный адрес, который браузер не может
заранее гарантированно зарезервировать. Возможен конфликт с другой локальной
программой. Это защита от ошибок, а не от скомпрометированного компьютера.
Технические границы описаны в [архитектуре Firefox](../development/FIREFOX_ARCHITECTURE.md).

## Безопасный отчёт о проблеме

Не публикуйте пароль, имя пользователя, частный адрес подключения, полный URL
со строкой запроса, профиль браузера, данные маршрутизации или историю
посещений. Для диагностики используйте очищенный отчёт из раздела
**Обслуживание / Maintenance**.

Обычные проблемы: [issue form](https://github.com/aVitomin/runet-censorship-bypass-mv3/issues/new/choose).
Уязвимости: [приватная форма GitHub](https://github.com/aVitomin/runet-censorship-bypass-mv3/security/advisories/new)
по [политике безопасности](../../SECURITY.md).

## English summary

This page covers published `0.0.4.0`; configuration-transfer privacy and the
unreleased workflow are covered in the [1.0 preparation guide](../development/UPCOMING_1_0_USER_GUIDE.md).

The extension needs host and proxy permissions to select routes and handle
configured proxy authentication. It contains no developer telemetry or
analytics service, but it is not a VPN and cannot guarantee anonymity, IP
hiding, or freedom from DNS leaks. Settings and optional proxy credentials are
stored in browser-local storage; saved passwords are not returned to the UI or
diagnostics. A selected proxy or local service can observe destination and
protocol-visible traffic. Never publish credentials, private proxy/source URLs,
browser profiles, routing data, or browsing history.
