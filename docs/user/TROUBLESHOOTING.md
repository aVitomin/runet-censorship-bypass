# Решение проблем

Начинайте с **Overview** и **Maintenance**. Запишите браузер и его версию,
версию расширения, глобальное состояние, режим текущего сайта и очищенный код
ошибки. Не публикуйте пароли, usernames, приватные proxy endpoints, URL с query
string, cookies, routing data или историю посещений.

## Расширение не загружается

### Chromium

1. Сверьте SHA-256 скачанного ZIP и распакуйте его заново.
2. В **Load unpacked** выберите папку, где `manifest.json` лежит прямо в корне.
3. Не выбирайте ZIP, родительскую папку или корень репозитория.
4. Не перемещайте установленную папку; при необходимости нажмите **Reload** на
   странице расширений.

### Firefox

Используйте Mozilla-подписанный XPI из опубликованного
[`v0.0.4.0`](https://github.com/aVitomin/runet-censorship-bypass-mv3/releases/tag/v0.0.4.0).
Публичной AMO-страницы для нового Gecko ID пока нет. Unsigned XPI предназначен
только для временного reviewer/development тестирования и не является обычной
пользовательской установкой.

Подробности: [установка](INSTALLATION.md).

## Apply не включает маршрутизацию

Проверьте текст состояния:

- **Setup required** — не выбрана обязательная конфигурация. Откройте
  **Automatic routing**, выберите доступный источник и повторите Apply.
- **Not applied** — изменения сохранены как черновик. Исправьте ошибки и нажмите
  глобальный **Apply configuration**.
- **Proxy candidate unavailable** — явному Proxy-правилу не хватает хотя бы
  одного включённого пригодного подключения.
- **Private access required** в Firefox — разрешите расширению работу в
  приватных окнах, затем повторите Apply.
- **EXT / Controlled externally** — сначала устраните внешнего владельца proxy
  settings; расширение не будет его перезаписывать.

Не очищайте browser storage как первый шаг: это удалит настройки и усложнит
диагностику.

## Сайт не открывается

1. Откройте popup на проблемной вкладке и проверьте Auto / Proxy / Direct.
2. Убедитесь, что нет **Not applied**.
3. Проверьте область правила: точный host либо домен с поддоменами.
4. Запустите **Connection check** в Maintenance.
5. Если используется Proxy, убедитесь, что соответствующее приложение или
   сервер доступен и его host/port/type сохранены правильно.
6. После успешного Apply обновите вкладку, чтобы повторить уже начатые запросы.

Connection check проверяет один контролируемый путь. Даже успех не доказывает
анонимность, отсутствие DNS-утечек или маршрут всех ресурсов страницы.

## Режим Proxy не имеет доступного подключения

Явное Proxy-правило не заменяется Direct или политикой автоматического
источника. Поэтому Apply блокируется, если нет пригодного кандидата.

1. Откройте **Proxy connections**.
2. Проверьте счётчик доступных подключений.
3. Включите и исправьте нужный локальный или пользовательский proxy server.
4. Нажмите **Save proxy settings**, затем глобальный Apply.

Не включайте случайный сервер только для прохождения проверки.

## Показан `EXT` или внешний контроль

Другое расширение, browser policy или администратор владеет proxy settings.
Runet Censorship Bypass снимает свою активную сессию и не очищает/не
перезаписывает чужую настройку.

1. Проверьте другие VPN/proxy extensions.
2. Проверьте browser policy, если устройство управляется организацией.
3. Отключайте внешний контроллер только если понимаете его назначение.
4. После освобождения настройки вернитесь в Overview и явно нажмите Apply.

Автоматического скрытого повторного включения нет.

## Firefox требует доступ к приватным окнам

Для безопасного управления общим Firefox proxy setting расширению нужен private-
window access. Откройте карточку расширения в `about:addons` и разрешите работу
в приватных окнах. Затем повторите Apply.

Если разрешение отозвано во время Active, приватные listeners исчезают,
маршрутизация блокируется, а интерфейс требует внимания. **Turn off / Clear**
должен оставаться доступен без повторной выдачи разрешения.

## Аутентифицированный прокси не работает

1. Откройте **Edit** нужного proxy connection.
2. Проверьте type, host, port и username.
3. Для замены или удаления пароля используйте явное действие **Replace / Clear**.
4. Сохраните настройки и нажмите глобальный Apply.
5. Повторите Connection check.

Сохранённый пароль не отображается снова. Пустое поле не означает, что пароль
можно извлечь; состояние **Keep** сохраняет существующее значение. В Firefox
после двух неудачных proxy-auth ответов запрос прекращается, чтобы браузер не
показывал неожиданное системное окно ввода и не зацикливал попытки.

## Tor, Tor Browser или WARP недоступен

Флаг Enabled не запускает локальное приложение и не обнаруживает его порт.

- **Tor service:** запустите службу и проверьте SOCKS5 `127.0.0.1:9050`.
- **Tor Browser:** запустите Tor Browser и проверьте SOCKS5
  `127.0.0.1:9150`.
- **WARP:** запустите настроенный локальный proxy и проверьте сохранённый
  endpoint; автоматического обнаружения нет.

Меняйте endpoint только если локальное приложение действительно использует
другой адрес. Затем сохраните настройки, нажмите Apply и запустите Connection
check.

## Turn off / Clear не вернул прежний proxy

1. Дождитесь завершения текущей Apply/Clear операции.
2. Проверьте, не показан ли `EXT`: чужую настройку расширение не очищает.
3. Повторите **Turn off / Clear** из popup или Overview.
4. Перезагрузите карточку расширения и снова проверьте состояние.
5. Если браузером управляет policy, восстановить настройку может только
   администратор.

Clear сначала выключает активную маршрутизацию и снимает только точно
принадлежащую расширению proxy-настройку. Правила и локальные routing data при
этом сохраняются.

## Firefox routing-data update недоступен

В `0.0.4.0` Firefox использует доверенный набор данных, включённый в пакет.
Удалённый release endpoint и публичный ключ пока не настроены, поэтому ручная и
фоновая проверка обновлений показывает **Unavailable / Not configured** и не
делает сетевой запрос. Встроенная автоматическая маршрутизация продолжает
работать; это состояние не исправляется пользовательским URL или ключом.

## Интерфейс долго показывает Working

Закройте и снова откройте popup или Options. Если состояние не меняется,
перезагрузите карточку расширения и воспроизведите действие один раз. Не
нажимайте Apply/Clear многократно: операции сериализованы, а кнопки временно
блокируются именно для защиты от дублей.

## Собрать безопасную диагностику

1. Откройте **Maintenance** и скопируйте очищенный диагностический отчёт.
2. Проверьте, что в нём нет посещённых URL, usernames, passwords, proxy
   endpoints, auth references, dataset hashes или floor identity.
3. Добавьте браузер/версию, версию расширения, наблюдаемое состояние и краткие
   шаги воспроизведения.
4. Не прикладывайте browser profile, NetLog или сырую историю без отдельного
   согласования: они могут содержать чувствительные данные.
