# 1.0.1 — Revived

**29 октября 2026:** [Chromium ZIP 1.0.1 опубликован](https://github.com/aVitomin/runet-censorship-bypass/releases/tag/v1.0.1).
Магазинные обновления и подписание Firefox 1.0.1 готовятся отдельно. В магазинах
и подписанном Firefox XPI пока доступна **1.0.0**.
[Установка](../../user/INSTALLATION.md).

## Изменения

- Название: **Runet Censorship Bypass — Revived** / **Обход блокировок Рунета — Revived**.
  Идентификаторы расширений и существующие ссылки магазинов сохраняются.
- Светлая, тёмная и системная темы в настройках и всплывающем окне обоих
  браузеров. Переключатель расположен в шапке настроек; выбор сохраняется
  локально и не меняет маршрутизацию.
- В Firefox настройки разделены на переключаемые секции, добавлен поиск
  правил, поля подключения сворачиваются. Переход между секциями сохраняет
  черновик. Ошибка ввода открывает нужный раздел и поле.
- В Firefox уточнено описание режима «Автоматически» для ручного источника
  правил. Сохранение и применение настроек остаются отдельными действиями.
- В Firefox добавлен явный выбор **SOCKS4A**: имя сайта передаётся прокси
  для разрешения DNS. Обычный SOCKS4 использует локальный DNS. Экспорт и
  повторный импорт в Firefox сохраняют выбранный режим.
  Chromium не поддерживает SOCKS4A и отклоняет импорт таких подключений
  без изменения настроек. Для DNS через прокси в Chromium используйте
  **SOCKS5**, если сервер его поддерживает.
- Puppeteer обновлён до 25.15.0 с совместимыми зависимостями, устраняющими
  найденную уязвимость Zod; `serialize-javascript` обновлён до 7.1.3 для
  устранения GHSA-m5mm-p8h7-m29v. Эти инструменты используются только при
  разработке; production-зависимости не изменены.

## Совместимость и выпуск

Расчётные минимумы в манифестах: **Chromium 108** и **Firefox 140**, включая
ESR на совместимой базе. Ожидается работа в настольных браузерах с необходимыми
API расширений; это не подтверждение каждой версии или каждого форка.
См. [основания и фактические проверки](../BROWSER_COMPATIBILITY.md).
Проверка ESR 153 на Debian/Linux остаётся отдельной дополнительной проверкой,
для которой подготовлен [сценарий](../qa/FIREFOX_ESR_153.md).
